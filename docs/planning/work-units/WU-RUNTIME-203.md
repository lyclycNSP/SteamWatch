# WU-RUNTIME-203 后台与托盘长时成本

## 背景与目标

现有 30 秒前台空闲/新进程短测不足以说明驻留性能。目标是在明确规模和环境下形成后台/托盘长时成本与采样/保存对照，并仅修复可证明的热点。

## 输入与依赖

依赖 BASE-201；建议 RUNTIME-202 后进行以固定恢复路径，最终输出供 RUNTIME-201。输入基线 docs/performance-v2.md。 权威来源：[SPEC](../../../SPEC.md)、[架构](../../architecture.md)、[数据](../../architecture/data-model.md)、[测试策略](../../test-strategy.md)。

## 允许修改范围

后台/快照/采样/保存相关路径与测量工具、性能报告、必要针对性回归；不以性能名义改变计量/保护合同。

## 非范围与兼容约束

不扩大产品能力，不操作主安装/正在游玩的游戏，不默认改 schema/协议/采样频率，不安装全局工具或 commit/push/发布。字段与退出保护保留；必要行为变更先同步合同及恢复方式。纯文档整理不得顺带改应用代码。

## 实施与验证

1. 固定机器/包/数据规模和测量时长；2. 分前台、托盘、受控活动采样，记录 CPU/工作集/private/周期及保存；3. 分析趋势而非单点；4. 有热点再改并同口径复测；5. 正常退出及账本/数据校验。

## 验收与完成标准

可复现命令、逐段测量与限制说明；未清缓存不称冷启动；无收益或权衡也如实记录。若无必要改动，可用充分证据结束，不强行重构。

## 风险与失败恢复

测试时长不等同真实长期稳定性；新样本目录隔离、不占用用户游戏，采样输出有界；失败保留现场、不伪造测量。
