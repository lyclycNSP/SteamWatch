# WU-RUNTIME-202 活跃会话退出故障恢复

## 背景与目标

已有目录 dirty/管道断开验证不能证明活跃游戏 ticks/提醒恢复。目标为受控活动会话保存失败后恢复计时和执行状态，无重复/遗漏结算。

## 输入与依赖

依赖 BASE-201 及既有运行/退出实现，不依赖 RUNTIME-201 最终完成；输出供 RUNTIME-201 集成。 权威来源：[SPEC](../../../SPEC.md)、[架构](../../architecture.md)、[数据](../../architecture/data-model.md)、[测试策略](../../test-strategy.md)。

## 允许修改范围

Runtime/存储/监控/退出相关代码、受控进程及原生故障探针、必要回归；不触及无关 UI 或安装器。

## 非范围与兼容约束

不扩大产品能力，不操作主安装/正在游玩的游戏，不默认改 schema/协议/采样频率，不安装全局工具或 commit/push/发布。字段与退出保护保留；必要行为变更先同步合同及恢复方式。纯文档整理不得顺带改应用代码。

## 实施与验证

1. 受控 steam/game 进程与独立 Stopwatch；2. 会话活跃时锁定账本并发起退出；3. 检查失败保留进程/草稿、解除锁后恢复采样；4. 核对 ticks 增量、重复循环/提醒、重试正常退出与重开；5. 如需原生注入，保持仅测试工具可达，不引入生产故障开关。

## 验收与完成标准

有源码与包身份、输入/时钟/账本数值、失败/恢复/重试证据；精度差异解释轮询误差；原生或服务级范围明确，真实 Steam 游戏仍交 ACCEPT-202。

## 风险与失败恢复

保存失败不能继续强退；故障锁必须 finally 释放，测试进程按正常协议退出，不遗留监听/监控停态。
