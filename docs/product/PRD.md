# SteamWatch 产品定义

本文件维护产品目的、范围、核心术语和业务规则。行为合同见 [SPEC](../../SPEC.md)，实际完成度见 本地 `STATUS.md`。

## 定位与用户

面向希望管理 Steam 游戏时间的 Windows 个人用户。应用本地运行、离线读取 Steam 数据、托盘常驻，帮助用户看到用量、设置限额并按选择提醒或关闭游戏。认证用于减少应用内绕过，不构成操作系统级强制管控。

## 目标与非目标

- 日常查看：明确今天/本周实测了多久、哪些规则生效、是否即将强退。
- 自我约束：提供全部游戏和单游戏的每日/每周限额，保留显式选择的执行策略。
- 可信统计：区分实测与估算，允许查看和审计修正，保护历史数据。
- 统一体验：游戏、统计、设置、帮助保持一致的原生视觉和可达操作。
- 专业交付：绿色版入口清晰；安装目标为当前用户 Inno EXE，满足兼容/恢复合同后切换。

2.0 首版不加入云账号、云同步、Windows Service、跨平台、临时放行、后台自动更新或活动日志页面。不要求兼容旧 Python config/timedata；1.2.0 用于能力/数据/效果比较，不冻结其代码实现。

## 用户流程

| 场景 | 用户流程 | 期望价值 |
| --- | --- | --- |
| 设置总预算 | 游戏首页→每日/每周总限额→保存 | 所有游戏共用预算，避免逐游戏设置遗漏 |
| 设置单游戏限额 | 搜索/选择游戏→双击或右键→编辑日/周规则 | 在游戏库内完成管理，无重复规则页 |
| 运行与约束 | 后台计时→提醒→显式强退策略倒计时 | 及时提示并按用户选择执行 |
| 查看历史 | 统计→日期/周期→实测/估算→来源或修正 | 理解数值来源，不把估算当作限制依据 |
| 维护与升级 | 导出备份/诊断→正常认证保存退出→更新或恢复 | 数据保留，失败后可继续使用 |

## 核心对象与业务规则

| 术语 | 产品含义与不变量 |
| --- | --- |
| 游戏 | AppID 是稳定身份；分类/筛选不改变监控范围 |
| 实测 | 应用识别运行会话累计的活跃时间，是限额依据 |
| 估算 | Steam 本地缓存差值或历史聚合；明确标识，不推测真实发生日/设备，不参与限额 |
| 规则 | 全局/单游戏×每日/每周同时约束，同一自然身份一条，无覆盖优先级 |
| 总用量 | 相加每个游戏的用量；多个游戏并行不改为时间区间并集 |
| 暂停限制 | 仍计时，停止提醒和强退；恢复给予新宽限 |
| 草稿 | 尚未保存的设置；认证取消或退出失败仍可继续编辑 |
| 完整备份 / 诊断 | 前者可含认证配置须妥善保管；后者脱敏，二者用途不同 |

## 成功标准

不设无基线的增长或性能数字目标。以能力对照无遗漏、历史数据与认证保护不弱化、统一交互可达、失败恢复可复现、安装闭环有证据衡量交付。测试层级和证据边界见 [测试策略](../test-strategy.md)；任务完成条件见 本地 `PLAN.md`。

## 平台与设计决策

目标 Windows 10/11 x64，继续 C#/.NET/WinUI 3，保留安装与绿色两种分发。最低平台声明和运行时配置以项目文件为准，不把声明等同于全系统验收。用户已确认第一版视觉与游戏库统一限额方向，见 [重设计方案](../redesign-v2.md)。
